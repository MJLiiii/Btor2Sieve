# Btor2Sieve Implementation Plan

> **For agentic workers:** Use subagent-driven development for isolated components and native execution for integration. Track evidence in docs/PROGRESS.md.

**Goal:** Deliver the C14 extraction and independent implication-validation product, with reproducible research evaluation.

**Architecture:** Strict BTOR2 parsing feeds word-level Z3 encoding. Untrusted syntax/semantic candidate generation feeds a separate validator, producing JSON/CSV/HTML and standalone SMT obligations.

**Tech Stack:** Python >=3.11, z3-solver, pytest, optional external SMT executable.

**Spec:** ../specs/2026-11-08-btor2sieve-design.md

## Global Constraints

* Preserve bit-vector widths and arrays; no integer arithmetic approximation.
* Property hypotheses are exactly not bad; never silently add environment assumptions.
* Accept only UNSAT implication obligations; report vacuity and UNKNOWN separately.
* Never inject property-implied constraints as assumptions into the original model.
* Bounded extraction, reproducible provenance, no fabricated performance claims.

## Review Focus

* Malformed or unsupported BTOR2 must fail with source/line diagnostics.
* BV signed arithmetic, overflow, shifts, and arrays must follow official semantics.
* Contradictory hypotheses must not inflate accepted-constraint statistics.
* Reuse across properties requires a new implication check for each target.
* Export/replay failures, partial batch errors, and HTML escaping must be visible.
